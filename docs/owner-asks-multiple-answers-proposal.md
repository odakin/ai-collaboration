# 問いの台帳で複数の問いにまとめて答える方針案

直前に示した問いの中身と推す答えを一行に並べ、本人の短い肯定でまとめて確定できるようにする。対象は、まとめて確かめられると明示した内向きの選択と作業方針に限る。送信・公開や保護された変更の承認は、それぞれの手順で対象を示して受ける。

## 現行と再現

現行の案内は「候補を 1 つだけ問いの中身で名指し、印は後ろに添えて確かめる」。一方、直前の返事に問いだけが並ぶ条件では、現行の `bind` が「全部おすすめで」を並びへの答えとして即時に複数へ結ぶ。今回つまずいたのは、結び先が未確定の答えを扱う `hook_prompt` と `_settle` の経路。既存の即時確定も確認を通す対象に含め、同じまとめ答えが表示順だけで確定する経路を残さない。

架空の問い三つと一時台帳で `UserPromptSubmit` と `PreToolUse` の本体を通した。「それで」で三つの候補が残り、「全部おすすめでいい」は拾われず、「はい。お願いします。」は肯定と認識されたが三つを挙げた行では結べなかった。「yoi」も認識されず、三つとも開いたままで `SendMessage` を止める判定が続いた。別入力の「全部おすすめで」は、一つの問いの並びだけが見える条件で三つに即時に結ばれた。現行の `board_asks.py --selftest` と `owner-asks.test.sh` は通過した。

## まとめて確かめる形

- はじめの対象は、内向きの `choice` と、準備・検討を進める `policy`。問いを立てる側が、この問いをまとめて確かめても別の承認を兼ねないと判定して台帳に明示する（本人側の操作は増やさない）。根拠の区分だけでは人への連絡・金額の決定も `choice` になりうる。外への送信・投稿・公開、対外的な約束や支払い、保護された原稿・規則・設定・hook の変更、道具の許可は対象外。台帳の根拠が `outbound`・`rule`・`protected` の問い、適用候補のファイルや保護検査の拒否理由を持つ問い、承認の照合に使う対象や文面を含む問いも除く。適格の記録がない既存の問いは個別の経路で扱う。言い直した問いは新しい内容で適格性を確認する。
- 「ぜんぶ」「全部おすすめで」「全部おすすめでいい」は、本人の発言全体が同じ向きの短い答えで、全部の指す範囲が一つの明示された問いの並び、または既にその並びから作った同じ窓の未確定候補、と定まるときに拾う。「両方」は二つが指せるときに限る。別の問いの並び、以前の返事、別の窓の問いは足さない。「全部」の指す範囲に一つでも対象外があれば、どの問いをまとめてよいか中身で示し直す。選択の対象が定まるまで全部の推定を保つ。
- 「それで」「おすすめで」のように結び先が未確定なら、同じ窓で既に示した候補から、どれにどう答えたと読むかを一行で明示できる。肯定が結ぶのはその行に明示した問いと答え。本人が「全部」と言った場合は、指された集合の全件を示す。台帳の問いと推す答えから確認行を組み立て、各項目の中身に印を添える。印だけ、要約で意味が変わった文、引用、別々の読みの行、承認など別の答えを求める表示と同居する返事では複数を確定しない。
- 確認行の例は「資料の並びは日付順にする (Q1)、見出しは短くする (Q2)、別表は一枚にまとめる (Q3)、の三つともこの案で進めると読みました。よいですか」。短い「はい」「よい」「はい。お願いします。」で確認する。`yoi` は全角半角・大小文字・末尾の句読点を正規化して、発言全体が短い肯定のときだけ拾う。`yoi` を足すのは、適格な問いの明示的な確認行への返答の経路だけ（問い一つの読み合わせにも使える）。「お願いします」「それで」は単独では複数への確認と読まない。保留・否定や問い返しと混じる言い方も複数の答えに読まない。既存の「答えではない」で推定を捨てる経路、個別に答え直す経路は使える。
- 台帳には、本人が答えた語、確認した語、見せた読み、確定した問いの印を一つの記録として残す。「それで」の後で「全部おすすめでいい」が範囲を明示したら、後者を答えの語、前者をそれ以前の読みの記録として残す。既にこの答えで同じ集合と推す案を見せているときは、同じ答えの繰り返しも確認と読める。直前に見せた問いと推す答えの版、未確定の答え、全件がまだ開いていることを台帳の書き込みロック内で照合してから一度に確定する。言い直し・取り下げ・別の窓での確定が一つでもあれば、残りだけへの確定や一問経路への読み替えを避け、改めて対象を示す。確定後、返事の一行目と台帳の一覧では結んだ問いを全件示す。

## 承認との境界

一度に結べる数を増やし、正しく確定した後は未確定の間の操作止めが解けるので、結び先の制限を変える提案に当たる。依頼側の検収と本人の方針確認を経て実装に進む。まとめ答えは問いへの答えを記録する機能に限る。発信先・送る全文、保護ファイルの名前・候補の SHA-256、道具の許可は、それぞれ従来の照合と承認で扱う。`policy` の確認済み記録を、保護された候補を当てる承認に流用しない。

同じターンに発信や保護された変更の承認の問い・ボタンがあると、台帳から対象を除くだけでは足りない。下流の承認器は会話の発言から直接承認を読むため、まとめ確認を出すターンには承認の表示を同居させず、別件への同意と読める場合は確定を保留する。別ターンで個別に聞く。実際の送信・変更の承認器を通した試験で、まとめ答えから承認が生じないことを採用条件にする。手入力 CLI が未確定の答えを確定できない条件も維持する。

## 試験の形

| 入力と場面 | 照合する結果 |
|---|---|
| 一つの並びに内向きの問い三つ。「それで」、続けて「全部おすすめでいい」、三つを示した確認行に「はい。お願いします。」 | 確認の直前まで未確定で操作止めが効く。確認後に三つだけが一度で閉じ、答え・確認・読みが保たれる。初手の「全部おすすめで」でも同じ。 |
| 一つの読み合わせへの `yoi`、三つの読み合わせへの `yoi！`。続けて単独の問い・確認行なし・別タスクの返事で `yoi` を試す | 適格で表示した読みだけが結ばれる。「yoi、でも二つ目は聞き直して」「全部ではない」「全部でいい？」、保留や質問混じりは複数に結ばない。 |
| 複数の問いの並び、別の窓の問い、別々の読みの行、引用・コード内の例、印だけ、同じ印の重複、二問への「三件とも」、三問への「両方」 | 範囲を広げず未確定のまま。どの問いを指すかの案内に出した答え方を全て試す。 |
| 内向きの問いと、送信・保護ファイル・道具の許可の問いが混じる。`choice` だが対外連絡を含む例も入れる | 「全部」で一部だけ確定することも、承認の記録や実行が出ることもない。仮の送り先と候補ファイルで、承認器を個別の承認まで進める対照例も通す。 |
| 確かめの前後に他の窓が問いを言い直す、閉じる、追加する。同じ確認が再実行される | 古い版・一部だけ・追加された問いへの確定と二重記録を防ぐ。台帳・操作止め・返答が同じ結果を示す。 |
| 既存の一問確定、印や並びを明示した個別の答え、推定の取り消し、圧縮後の再表示 | 元の意味で動く。`Stop` の返答チェックでは確定した全件の中身を確認する。 |

エンジンの `--selftest` に状態と記録の検査を入れ、`owner-asks.test.sh` では一時台帳と架空の会話で `UserPromptSubmit` → `PreToolUse` → `Stop` を通す。対象外の問いを混ぜる検査と、古い版を検出する検査は、それぞれ対応する判定を外すと失敗することまで確認する。

## 採らない案と未確認

- 確認行から印を拾って全部結ぶ案。再掲した問いや別々の読みを一つの意図に合成できてしまうため、一行の内容と問いの版を照合する形を推す。
- 「全部」で窓の開いた問いを一括確定する案。別件や見えていない問いを巻き込む。表示した範囲を確かめてから確定する形を推す。
- `yoi` を通常の一問への答えや承認にも足す案。短語が指す内容は直前の明示的な読みで決まるため、確認の経路だけに足す。
- 依頼の実例で三つの問いがそれぞれどの根拠で立ったか、当時の画面に別の承認の問いやボタンがあったかは未確認。依頼側の検収では、実例の問いの種類だけを照合し、全件をこの方針で扱えるか判断する。現行の再現は合成例で済ませた。下流の承認器を含む結合試験、表示や圧縮後の実画面での検査は実装段階に残る。
